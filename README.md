# Router.net

سوق الراوتر والسويتش (Next.js 14 + Supabase). يشتغل بدون قاعدة بيانات ببيانات تجريبية، وبمجرد ربط Supabase يقرأ ويكتب منها.

## قاعدة البيانات
1. أنشئ مشروع على supabase.com.
2. من SQL Editor شغّل بالترتيب: `0001_init.sql` ثم `0002_auth_notifications.sql` ثم `0003_full_features.sql` ثم `0004_logistics_refunds_docs.sql` ثم `0005_ops_hardening.sql` ثم `0006_final_features.sql` (أو `supabase db push`).
3. **الدخول بـ Google**: Supabase > Authentication > Providers > Google (Client ID/Secret من Google Cloud)، وفي URL Configuration ضع رابط Vercel في Site URL و Redirect URLs. الدخول بالإيميل وكلمة المرور شغال مباشرة.
4. **أول أدمن**: سجّل دخول مرة بحسابك ثم شغّل في SQL Editor:
   `update profiles set role='admin' where email='you@gmail.com';`
5. **إخفاء صفحات ديناميكيًا**: `insert into role_permissions(role,page,allowed) values ('support','returns',false) on conflict (role,page) do update set allowed=false;`

## بوابة الدفع
تجريبية بالكامل (`/pay/[id]`): لا تتصل بأي بنك ولا تخصم مبالغ، وتحدّث حالة الدفع والطلب وترسل إشعارات.

## النشر على Vercel
1. ارفع المجلد على GitHub ثم Import في Vercel (Framework: Next.js تلقائيًا).
2. أضف Environment Variables من `.env.example`:
   NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY (سرّي، للسيرفر فقط).
3. Deploy.

## تشغيل محلي
npm install && npm run dev

## الخطوة التالية (حسب الوثيقة)
لوحات التحكم (أدمن/شركة/دعم/شحن)، دخول OTP، بوابة دفع (Paymob/Fawry)، إشعارات، مرتجعات. الجداول والصلاحيات جاهزة لها في الـ migration.

## إعدادات إضافية
- **الصور:** الـ migration الثالث ينشئ bucket اسمه `product-images` تلقائيًا.
- **الإيميل للإشعارات:** أنشئ حساب على resend.com وضع في Vercel: `RESEND_API_KEY` و`MAIL_FROM` و`WEBHOOK_SECRET` (أي نص سري). ثم Supabase > Database > Webhooks: جدول `notifications` حدث INSERT، النوع HTTP Request، POST إلى `https://موقعك/api/notify-email` مع Header: `x-webhook-secret` بنفس القيمة. بدون هذه الخطوة تبقى الإشعارات داخل الموقع فقط.
- **الفاتورة:** صفحة `/invoice/[id]` تعمل بزر طباعة / حفظ PDF من المتصفح.
- **الكوبونات:** من لوحة الأدمن > الكوبونات (الكود يتحول لحروف كبيرة).
- **عمولة الشركة:** `update companies set commission_pct = 8 where name = '...';`

## الميزات
سلة متعددة، دفع تجريبي، مفضلة، عناوين، بيع جهاز مستعمل (يتحول لمنتج عند موافقة الأدمن)، رفع صور، كوبونات وخصومات، بحث وفلاتر، تتبع الطلب، تذاكر بمحادثة، مرتجعات، تقارير، محفظة وسحب أرباح، سجل عمليات، إشعارات داخلية وبريدية.

## الشحن والاسترداد والمستندات (migration 0004)
- **الشحنات:** الأدمن يعيّن المندوب (يحتاج حسابًا بدور `courier`)، والمندوب يرى شحناته فقط ويكتب رقم التتبع ويحدّث الحالة. العميل يستلم إشعارًا برقم التتبع.
- **COD:** عند تسليم الشحنة تتحول دفعة الدفع عند الاستلام إلى "مدفوع" تلقائيًا.
- **الإلغاء:** العميل يلغي طلبه قبل الشحن: يرجع المخزون وتُسترد/تُبطل الدفعة.
- **المرتجع:** عند "تم استلامه" يرجع المخزون مرة واحدة فقط، وعند "تم الاسترداد" تتحول الدفعة إلى "مسترد" والطلب إلى "مرتجع". الاسترداد الفعلي للفلوس يتم خارج المنصة لأن البوابة شكلية.
- **المستندات:** تُرفع في bucket خاص `company-docs` ولا يراها غير صاحبها والأدمن/الدعم (روابط مؤقتة 5 دقائق).
- **أمان:** الاعتماد والعمولة للأدمن فقط، والعميل لا يعدّل غير إلغاء طلبه، وقرار المرتجع للدعم والأدمن.

## migration 0005
- **إصلاح مهم:** سجل حالة الطلب كان يفشل عند تغيير الحالة من لوحة التحكم (صلاحيات)، وتم إصلاحه. ويظهر الآن مين غيّر الحالة.
- **المخازن وإعدادات المنصة** (رسوم الشحن، وشحن مجاني فوق مبلغ) من لوحة الأدمن، وشاشة **الصلاحيات** لإخفاء صفحات كل دور.
- **التذاكر:** أقسام وربط بطلب وتعيين مسؤول، والعميل يؤكد الحل أو يعيد الفتح.
- **المرتجع:** لكل منتج مع صور، والشركة توافق أو ترفض ثم يقرر الدعم والأدمن.
- **الحساب الموقوف:** يُسجَّل خروجه ولا يشتري، ويفقد أي صلاحيات في قاعدة البيانات. نسيت كلمة المرور تعمل عبر `/reset-password` (أضف الرابط في Redirect URLs في Supabase).
- **لحظي:** الإشعارات عبر Realtime. **SEO:** metadata وJSON-LD وsitemap وrobots (اضبط `NEXT_PUBLIC_SITE_URL` لنطاقك).

## migration 0006 والمزايا الأخيرة
- **إشعارات وعروض:** من لوحة الأدمن لفئة محددة. **تنبيهات أمان:** عند تغيير كلمة المرور أو الدخول من جهاز جديد.
- **الطلب متعدد الشركات:** كل شركة تجهّز منتجاتها فقط (بانتظار/مؤكد/قيد التجهيز/جاهز)، ويتحرك الطلب تلقائيًا عندما تجهز كل الشركات. لم تعد الشركة تغيّر حالة الطلب كله.
- **مهلة الدفع:** الطلب الإلكتروني غير المدفوع يُلغى بعد ساعتين ويرجع مخزونه (يتطلب pg_cron، وإلا استدعِ `select expire_pending_orders();` دوريًا).
- **الدفع الإلكتروني:** تحكّم فيه من إعدادات المنصة (`online_payments` = 0 يخلي الدفع عند الاستلام فقط). **قبل استقبال عملاء حقيقيين عطّله أو اربط بوابة حقيقية.** وصفحة الدفع التجريبية صارت تتحقق أن الدافع هو صاحب الطلب.
- **SMS اختياري (Twilio):** `TWILIO_SID` و`TWILIO_TOKEN` و`TWILIO_FROM`، لرقم التتبع وخروج الشحنة للتسليم.
- **تعديل المنتج الكامل** (وصف، صور، قسم، مخزن) من زر "تعديل كامل"، وسجل العمليات يعرض المنفّذ، وترقيم صفحات للمتجر، وحد للطلبات على الكوبون والدفع وإتمام الطلب.
- **الاختبارات:** `npm test` (منطق الأسعار والكوبونات والحد وتناسق إعدادات اللوحات).
